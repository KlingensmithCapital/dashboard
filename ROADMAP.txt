SECTION 1: WHAT THE PRODUCT IS
═══════════════════════════════════════════════════════════════

The PM Cockpit is a personal capital operating system for a solo portfolio manager.
It is NOT a retail brokerage app. It is a decision cockpit. Every feature exists to
answer one of three questions:

  1. How much capital do I have and where is it?
  2. What is happening in the portfolio right now?
  3. What deserves my attention today and why?

The primary user is the PM — one person — who manages a multi-account equity book
across Schwab brokerage accounts (taxable, Roth IRA, traditional IRA, HSA) plus
external savings (HYSA, etc.).

The design philosophy is: calm, premium, decisive. No gamification. No noise.
Every pixel earns its place by helping the PM act faster or safer.

SECTION 3: DATABASE SCHEMA (SUPABASE)
═══════════════════════════════════════════════════════════════

All tables have user_id (uuid, FK to auth.users) and RLS policies enforcing
"owner only" (auth.uid() = user_id). All tables have cascade delete on user removal.

TABLE: accounts
  id uuid PK
  user_id uuid FK
  name text                  -- "Roth IRA (4282)", "Taxable (5092)", "HYSA"
  institution text           -- "Schwab", "Ally", etc.
  type text                  -- "roth_ira", "taxable", "hsa", "traditional_ira", "savings"
  external_id text           -- Schwab account number (used to key sync, prevent duplicates)
  created_at timestamptz

TABLE: holdings
  id uuid PK
  user_id uuid FK
  account_id uuid FK -> accounts.id
  ticker text
  name text                  -- Security description
  shares numeric
  cost_basis numeric          -- Per-share cost basis
  current_price numeric
  market_value numeric        -- shares * current_price
  weight_pct numeric          -- market_value / total_equity * 100
  pnl_pct numeric             -- (current_price - cost_basis) / cost_basis * 100
  status text                -- "green", "amber", "red"
  theme text                 -- Sector/thesis tag
  is_active boolean          -- False when position was synced away (sold)
  last_synced timestamptz
  created_at timestamptz

TABLE: balances
  id uuid PK
  user_id uuid FK
  account_id uuid FK -> accounts.id
  date date
  value numeric               -- Total account liquidation value (equity + internal cash)
  cash_available numeric      -- Cash/sweep balance within the account
  UNIQUE (user_id, account_id, date)

TABLE: transactions
  id uuid PK
  user_id uuid FK
  account_id uuid FK
  ticker text
  type text                   -- "buy", "sell", "dividend", "contribution", "withdrawal"
  shares numeric
  price numeric
  total numeric
  date date
  notes text

TABLE: theses
  id uuid PK
  user_id uuid FK
  ticker text
  title text
  body text                   -- Why this position is owned
  kill_criteria text          -- What must remain true or position is exited
  status text                 -- "active", "archived", "watching"
  conviction integer          -- 1-10
  updated_at timestamptz

TABLE: thesis_changes
  id uuid PK
  user_id uuid FK
  thesis_id uuid FK -> theses.id
  note text
  changed_by text             -- "pm" or "agent"
  created_at timestamptz

TABLE: catalyst_events
  id uuid PK
  user_id uuid FK
  ticker text
  title text
  type text                   -- "earnings", "macro", "regulatory", "position_review"
  urgency text                -- "today", "high", "normal", "low"
  due_date date
  is_complete boolean
  linked_holding_id uuid FK   -- Direct link to holdings (not yet used)
  notes text

TABLE: ideas
  id uuid PK
  user_id uuid FK
  name text                   -- Idea name or thesis title
  ticker text
  note text                   -- Thesis summary
  score integer               -- Conviction 0-100
  status text                 -- "new", "watch", "promote", "archive"
  source text                 -- "pm", "agent"
  created_at timestamptz

TABLE: morning_briefs
  id uuid PK
  user_id uuid FK
  date date
  market_summary text         -- Short narrative
  portfolio_notes text        -- Position-specific observations
  flight_plan jsonb           -- Structured action items [{action, ticker, priority}]
  market_context jsonb        -- Macro/sector notes
  watchpoints text[]          -- Array of tickers/themes to watch
  generated_at timestamptz
  UNIQUE (user_id, date)

TABLE: agent_runs
  id uuid PK
  user_id uuid FK
  agent text                  -- "morning_brief", "thesis_review", etc.
  status text                 -- "success", "error"
  input jsonb
  output jsonb
  error text
  duration_ms integer
  created_at timestamptz

TABLE: documents
  id uuid PK
  user_id uuid FK
  name text
  type text                   -- "statement", "research", "note"
  storage_path text           -- Supabase Storage path
  parsed boolean
  parsed_at timestamptz

TABLE: expenses
  id uuid PK
  user_id uuid FK
  category text
  description text
  amount numeric
  date date
  source text
  is_recurring boolean

TABLE: schwab_tokens
  user_id uuid PK FK
  access_token text
  refresh_token text
  expires_at timestamptz

SECTION 6: KNOWN BUGS & REQUIRED FIXES (do these before new features)
═══════════════════════════════════════════════════════════════

BUG-01: /api/debug is public — leaks user data
  File: app/api/debug/route.ts
  Fix: Add auth check at top (verify user via supabase.auth.getUser()) or delete the route.

BUG-02: /api/prices/quote is unauthenticated — could be rate-abused
  File: app/api/prices/quote/route.ts
  Fix: Add auth check or move to a server action inside the component.

BUG-03: Morning brief JSON extraction uses fragile regex
  File: app/api/brief/generate/route.ts
  Fix: Use Claude's JSON mode or wrap the prompt with explicit delimiters.
  Current: Regex match on response text to extract JSON block.
  Better: Instruct Claude to respond ONLY with JSON, or use tool_use/json mode.

BUG-04: Schwab sync has no transaction safety
  File: app/api/schwab/sync/route.ts
  Fix: If any position upsert fails, log the error and continue but flag partial sync.
  Better: Use a staging approach — write to temp state, then commit all at once.

BUG-05: Weight calculation is inconsistent between sync and page
  Sync calculates: weight = marketValue / totalValue (Schwab account liquidation value, includes cash)
  Page calculates: weight = marketValue / Σ(holdings.market_value) (equity only)
  Fix: Standardize. Recommend: weight = marketValue / Σ(holdings.market_value) (equity-only denominator).

BUG-06: Portfolio table position count shown to user could include duplicates
  If the Supabase DB cleanup SQL was not run, old accounts without external_id remain.
  Fix: Run the cleanup SQL described in the setup notes.
  SQL: DELETE FROM holdings WHERE account_id IN (SELECT id FROM accounts WHERE external_id IS NULL);
       DELETE FROM accounts WHERE external_id IS NULL;

BUG-07: AutoSync double-fires on React Strict Mode dev
  File: app/components/AutoSync.tsx
  Fix: The useRef flag already prevents double-fire in prod. No prod bug, but noisy in dev.

DELETE FROM holdings WHERE account_id IN (SELECT id FROM accounts WHERE external_id IS NULL);

SECTION 10: DESIGN SYSTEM RULES
═══════════════════════════════════════════════════════════════

Colors are semantic — do not use color for decoration. Use color only to signal state.

  Green (emerald-*)   = positive, healthy, good signal
  Amber (amber-*)     = caution, watch, needs attention
  Red/Rose (rose-*)   = negative, danger, action required
  Sky (sky-*)         = informational, cash, liquidity
  Slate (slate-*)     = neutral, labels, secondary text

Status badge classes:
  GREEN:  bg-emerald-50 text-emerald-700 ring-emerald-200
  AMBER:  bg-amber-50   text-amber-700   ring-amber-200
  RED:    bg-rose-50    text-rose-700    ring-rose-200
  CASH:   bg-sky-50     text-sky-600     ring-sky-200

Typography:
  Display/headings:   Cormorant Garamond (font-serif)
  UI/data:            Manrope (font-sans)
  Section labels:     11px, uppercase, tracking-[0.28em], text-slate-400
  Metric values:      text-xl or text-base, font-semibold, tracking-tight

Layout:
  Max width: max-w-[1600px], centered, px-4 sm:px-6 lg:px-8
  Gap between sections: gap-5
  Panels: rounded-2xl, bg-white (or bg-slate-50 for interior cards)
  Card borders: border border-slate-100

Numeric formatting helpers in page.tsx:
  fmt$(n)     — formats dollar amounts (M suffix for millions, comma for thousands)
  fmtPct(n)   — formats percent with sign (+15.87% or -3.22%)
  Always guard: if (!isFinite(n)) return "—"

SECTION 11: AI AGENT IMPLEMENTATION NOTES

ANTHROPIC SDK USAGE:
  - SDK: @anthropic-ai/sdk (not Vercel AI SDK)
  - Rationale: generate-and-store pattern (brief generated, stored in DB, page reads DB)
  - Model: claude-sonnet-4-6 (check for latest model ID before each run)
  - Do not stream — generate full response and store

RECOMMENDED PROMPT PATTERN FOR AGENTS:
  System: "You are a portfolio management assistant for a solo PM at Klingensmith Capital.
           You respond only with valid JSON matching the schema provided.
           Do not include markdown, code fences, or explanation — only JSON."
  User: [Portfolio context as structured text]
  Schema: [JSON schema for expected output]

JSON EXTRACTION:
  Do NOT use regex to extract JSON from response text.
  Instead, parse the full response as JSON: JSON.parse(response.content[0].text)
  If this fails: the prompt is not returning clean JSON — fix the system prompt.

AGENT RUNS LOGGING:
  Always write to agent_runs table on success and failure.
  Fields: agent (name string), status, input (jsonb), output (jsonb), error (string), duration_ms

DATA CONTEXT TO INCLUDE IN AGENT PROMPTS:
  For morning brief: holdings (with weights), balances, catalyst_events, ideas, theses
  For thesis review: theses (with kill_criteria), holdings P/L, thesis_changes history
  For idea research: idea name/ticker, similar holdings in portfolio, market context
